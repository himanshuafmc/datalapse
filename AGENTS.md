# AGENTS.md

Instructions for AI coding agents (and humans) working on this repository. Read this before changing code.

## What this is

Datalapse is a browser app that turns a story spec (JSON: data plus scenes) into video frames on a Canvas and encodes them with WebCodecs. The original scenes are a port of the Python engine in `reference/python/engine.py`, and the port is held to that engine by tests. No server, no framework, and no network access at runtime unless a person turns on one of the opt-in online features (see "Network" below).

## Layout

| Path | Role | Rules |
|---|---|---|
| `src/core/` | Numeric and text helpers ported from Python, NumPy and matplotlib; layouts per format | Pure functions. Match Python exactly, including rounding and float summation order. Covered by `tests/unit.test.mjs` fixtures. |
| `src/scenes/` | One file per scene type: the plug-in boundary | A scene only reads its spec, its env and the `fig` it is given. No DOM, no globals, no randomness. |
| `src/render/` | `Fig` (matplotlib-like drawing on Canvas), background, fonts, flags, world outlines, `Video` | `Video.drawFrame(ctx, fmt, g)` must be a pure function of the spec and the frame number. |
| `src/export/` | Video (H.264 MP4, VP9 WebM, MediaRecorder fallback), GIF, Shorts, thumbnails, subtitles, audio description, web page, share links, fingerprint | Never upload anything. Handle back-pressure and cancellation. |
| `src/audio/` | Music library (IndexedDB), beat detection, mixing, narration timing | Audio never leaves the device; stories keep only ids. |
| `src/data/` | CSV import, country names, drama finder, fact checks, data doctor, the automatic story writer | Plain functions; tested in `tests/unit.test.mjs`. |
| `src/spec/` | Validation, translations, plain-language commands, the AI prompt | Every spec field must be validated here with an actionable message. |
| `src/app/` | The studio UI (vanilla JS) and the web-page player (`viewer.js`) | May use the DOM. Talks to the engine only through `Video` and the spec. |
| `src/stories/bundled.js`, `stories/` | Generated from `reference/python` by `tools/export_stories.py` | Do not edit by hand. `src/stories/showcase.js` is hand-written. |
| `src/render/fontData.js`, `flagData.js`, `worldData.js`, `src/data/countryData.js`, `refData.js`, `src/core/hookWalks.js` | Generated by the scripts in `tools/` | Do not edit by hand. |
| `cli/` | Command-line renderer (`datalapse render story.json`) | Drives the built page in headless Chromium; same pixels as the studio. |

## Adding a scene type

1. Create `src/scenes/MyScene.js` with a class extending `Scene` from `common.js`:
   - `static type = 'myScene'`, `static label = 'My scene'`, `static defaults = { ... }`.
   - `static paced = true` if its length comes from a `pace` over data time (it then needs `data` and `pace`, which the validator checks). Scenes reading several datasets list them in `static dataKeys`.
   - `static validate(spec, { w, ds, datasets, errs })`: push plain-language errors for its own fields.
   - `constructor(spec, env)`: read the spec, build formatters (`makeFormatter`), look up data with `env.dataset(id)`, colours with `env.colorOf(name, spec.colors)`, names on screen with `env.label(name)`, flags with `env.icon(name, spec)`.
   - `get duration()`: seconds (from a `Pace` for data scenes).
   - `prepare(L, fps)`: precompute per-frame arrays for layout `L` (`L.fmt` is `landscape`, `vertical`, `square` or `portrait`). Must be deterministic.
   - `draw(fig, L, i, t)`: draw frame `i` (time `t` seconds into the scene) with `fig.text`, `fig.rect`, `fig.roundedBox`, `fig.icon`, `fig.custom` and `fig.axes(...)`. Coordinates are figure fractions from the bottom left; font sizes are pixels from `L.fs`. Layers below z-order 20 move with the camera; titles and captions (20 and up) stay still.
   - Optional `describe(i)`: one sentence of what frame `i` shows, for the audio description track.
2. Register it in `src/scenes/registry.js`.
3. Add its fields to `SCENE_FIELDS` and a default to `newScene()` in `src/app/inspector.js`.
4. Document it in `docs/STORY_SPEC.md` and in `SPEC_CHEATSHEET` (`src/spec/prompt.js`), so AI-written stories can use it. Add any new text fields to `SCENE_TEXT` in `src/spec/translate.js`.
5. Add a test: at least that a spec using it validates and draws in all four formats (see the showcase test in `tests/unit.test.mjs`).

## Invariants

- **Parity with the Python engine.** Any change to `src/core`, `src/render/fig.js` or a ported scene must keep `npm run parity` passing. New features must be off by default so existing stories render exactly as before. If you intentionally change the look, change the Python engine the same way or explain the divergence in the pull request.
- **Determinism.** The same spec and frame number always give the same pixels. No `Math.random()`, no `Date.now()` in rendering.
- **Backward compatibility.** Stories are files people keep. New fields need defaults; never rename or remove a field without a migration in `Video` or the validator.
- **Network.** The standalone build has `connect-src 'none'`: nothing is fetched. The only exceptions are the opt-in online features in `src/online/` (public data catalogue, voice model download). They are off until a person turns them on, can reach only the hosts listed in `src/online/hosts.js`, and the build that includes them adds exactly those hosts to its Content-Security-Policy. Don't add fetches, CDNs, analytics or remote fonts anywhere else.
- **Dependencies.** Runtime dependencies: `mp4-muxer`, `webm-muxer`, `gifenc`. Adding one needs a reason in the pull request.
- **Plain language in the UI.** Labels say what a person recognises ("Captions", "Always show"), errors say what went wrong and how to fix it.

## Checks before you open a pull request

```bash
npm test          # always
npm run build
npm run verify    # UI flows, screenshots in tests/screenshots, real exports (video, Short, GIF, web page, share link)
npm run parity    # when touching src/core, src/render or src/scenes (needs Python with numpy, pandas, matplotlib)
```

Look at the screenshots `npm run verify` writes (desktop and phone, light and dark, all four formats). A change that looks wrong is wrong even when the tests pass.

## Regenerating generated files

```bash
npm run stories    # stories/*.json, src/stories/bundled.js, src/core/hookWalks.js (from reference/python)
npm run fonts      # src/render/fontData.js (needs fonttools and brotli)
npm run fixtures   # tests/fixtures/python_expected.json (needs numpy and matplotlib)
node tools/build_countries.mjs   # src/data/countryData.js
node tools/build_flags.mjs       # src/render/flagData.js (needs Playwright)
node tools/build_world.mjs       # src/render/worldData.js
node tools/build_refdata.mjs     # src/data/refData.js (population, US CPI)
```
